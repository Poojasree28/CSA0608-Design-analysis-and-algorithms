## 9.1 Aim

To collect and compare the experimental performance of Linear Search, Iterative Binary Search, and Recursive Binary Search using different dataset sizes. The performance is measured using execution time and the number of comparisons.

## 9.2 Experimental Procedure

1. Create datasets containing 1,000, 10,000, 100,000, and 1,000,000 student registration numbers.
2. Use the same sorted dataset for all three algorithms.
3. Test each algorithm with a registration number at the last position and with a key that is absent.
4. Record the number of comparisons and execution time.
5. Repeat each test five times and calculate the average execution time.
6. Present the results using tables and graphs.

## 9.5 Analysis of Experimental Results

**Linear Search:** Linear Search checks registration numbers sequentially. When the search key is absent, it examines all the elements. Therefore, the number of comparisons increases linearly with the dataset size.

**Iterative Binary Search:** Iterative Binary Search repeatedly divides the search interval into two halves. Consequently, the number of comparisons increases logarithmically as the dataset grows.

**Recursive Binary Search:** Recursive Binary Search follows the same divide-and-conquer strategy as Iterative Binary Search. It has similar comparison-count growth, although recursive function calls may introduce additional execution overhead.

As the dataset increases from 1,000 to 1,000,000 records, Linear Search performs many more comparisons than either Binary Search approach. This demonstrates the advantage of Binary Search for large, sorted student databases.

## 9.6 Conclusion

The experimental analysis compares the three searching algorithms using consistent datasets, comparison counts, and execution times. Linear Search has linear worst-case growth, whereas Iterative Binary Search and Recursive Binary Search have logarithmic worst-case growth.
